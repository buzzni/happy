# Saycode API URL 공통 규칙

## 요구사항

- `{NAME}_SAYCODE_API_URL` 환경변수로 플랫폼 API를 발견한다. 이름은 대문자·숫자·밑줄을 사용하고 비어 있지 않다.
- 특정 LLM/음성 이름에 한정하지 않는 공통 지침을 happy-cli가 소유한다.
- 등록된 호출 명세와 사용 안내로 메서드·경로·인증·입력을 결정하며 suffix만 보고 추측하지 않는다.
- 기본 모델을 따르되 사용자가 요청한 허용 모델로 변경할 수 있다. 고객 앱의 모델 설정과 현재 코딩 에이전트 모델을 혼동하지 않는다.
- 환경변수의 값과 비밀 키를 지침에 삽입하지 않는다. 공급자 키를 고객에게 재요청하거나 직접 호출로 우회하지 않는다.
- Claude 로컬/리모트는 시스템 지침, Codex는 developer instructions, Gemini는 최초 세션 문맥에 제공한다. 후속 사용자 메시지에 안내를 반복 추가하지 않는다.
- 기존 Saycode 시스템 지침 OFF 설정을 존중하며 재활성화도 반영한다.

## 범위

이번 커밋은 happy-cli 공통 규칙만 반영한다. API 등록/조직 적용 분리 UI, 환경변수 자동 연결, 등록 명세 전달 경로와 office 모드 구현은 후속 작업이다. 기존 dev-studio 미커밋 게이트웨이 구현과 vendor 소비 포인터는 이 커밋에 넣지 않는다.

## 수용 기준

1. 네 실행 경로의 세션 지침에 같은 규칙이 포함된다.
2. Saycode master OFF면 규칙이 빠지고 다른 운영 지침은 유지된다.
3. Codex/Gemini 후속 사용자 메시지에는 규칙이 반복되지 않는다.
4. Gemini는 규칙의 유효 ON/OFF가 바뀌면 세션을 갱신한다.
5. 코드 타입 검사·빌드·관련 회귀 테스트 통과 후 한글 커밋을 작성한다.
