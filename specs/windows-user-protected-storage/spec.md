# Windows 사용자 암호화 저장 Spec

> 작성일: 2026-10-09 / 상태: 승인된 방향의 구현·검증 중

## 목표
회사 Windows의 상위 폴더 ACL 때문에 로그인·PC 연결을 진행하지 못하는 문제를, 보호 수준을 사용자가 선택하는 모달 없이 앱의 암호화 저장으로 해결한다.

## 요구사항
- R1. 로그인·Desktop 머신 seed/connection·Happy PC 연결 키는 Windows 사용자 범위 암호화로 저장한다. 키 사본(재로그인 identity, 백업/rotation, 임시 세션)과 daemon 제어 secret도 함께 조사·보호한다.
- R2. Windows 사용자 암호화 성공·읽기 검증을 완료한 경로만 자동 사용한다. 암호화 불가·실제 쓰기 거부는 평문 저장이나 새 키 발급으로 우회하지 않는다.
- R3. 기존 seed/deviceKey/machineId/Happy machineKey와 대화 연결을 보존한다. 읽기/복호화 실패를 신규 설치로 처리하지 않는다.
- R4. 기존 평문은 원본 객체의 귀속·무결성을 검증한 경우에만 전환한다. 검증할 수 없는 파일은 보존하고 명확한 오류를 표시한다. 서버 계정 소유권은 로컬 파일 출처 증명을 대신하지 않는다.
- R5. Windows 암호문 읽기가 Desktop·Happy 모든 소비자에서 동작한 뒤 동의 경로를 대체한다. macOS/Linux 저장 계약·서버 프로토콜은 유지한다.
- R6. 도움말/복사에는 오류 단계와 코드만 전달한다. 비밀을 argv·env·로그에 싣지 않는다.

## 비목표
고객 ACL/보안 프로그램 변경, 광역 SID 신뢰, 동의 자동 클릭, 암호화 실패 시 평문 fallback, 새 머신 발급으로 기존 상태 우회, Happy/npm 공개 배포와 공식 설치판 release.

## 완료 기준
실제 제한된 Windows 토큰에서 거부된 ancestor 유지 + 암호화 왕복 + 타 사용자/변조/경로 교체 거부 + 재시작/재설치 identity 연속성 + 실제 daemon/기존 대화 검증. 각 단계의 미수락은 구분한다.
