# Explicit personal Claude selection

This change targets official CLI release `1.1.10-aplus.371`; initial development was based on the Desktop-pinned `.368` commit.

- `ai-credential:personal-claude-accounts` is a customer-bound read. Only journal/provenance-verified OAuth identities are returned, with an opaque accountRef and roster metadata, never credentials. An ambiguous default remains forbidden; manual choice names the exact reference.
- Capability `personalClaudeSelectionVersion: 1` accompanies supported organization binding machinery. A fresh spawn carries `personalSelection` alongside its unused organization authority. The daemon verifies both scopes and the separate manual-purpose 60-second consent, consumes its nonce, applies only the selected personal credential and captures only accountRef in the existing resume record. No PC-global switch or login mutation occurs.
- Session control `prepare-manual` prepares an exact-account offer even with organization quota left. Acceptance verifies live authority and exact identity, then commits its secret-free choice before applying credentials at a request boundary. Current responses are preserved. Automatic fallback retains quota/error requirements and automatic organization return; manual selection stays personal.
- Cold resume rechecks current authority and identity. Rebinding an organization authority preserves the personal choice. An organization-only resume cannot reuse a live manual process; an idle manual session returns only after resolving organization credentials and durably clearing the marker before launch. Persistence failure refuses launch.
- Proofs/credentials are never stored in resume metadata. Request environment cannot inject the marker. Malformed markers and missing/changed personal identities fail closed. Channel requests cannot spend the interactive personal lease.
- Desktop owns its latest local personal-use allowance and delivery checks. Supported runtime/server and the member's dedicated local PC are required; remote/shared/managed one-shot expansion and official publication are outside this source change.

Revisit this contract if manual personal sessions must start without an organization authority, or if unattended/remote personal execution becomes a requirement.

Happy-wire was built from the exact pinned source in this worktree. Desktop's isolated macOS Electron journey was recorded and directly reviewed (Desktop context J); it used fake local RPC, not a real provider or PC-global switch. At that initial source stage, official publication, pin/install changes, push and deployment had not been performed. Local node_modules and .aplus verification artifacts are not source changes.

Clean-code review (2026-10-30): retained the exact prepared authority object through the real spawn gate while giving only the selected personal environment to the child. Real launch-gate regressions include replay, expiry, revocation and generation change. Generic polling no longer consumes manual confirmation; ordinary rebind preserves the marker atomically, explicit organization return clears it, and the redundant second resume write was removed. The related ten-file source run passed 473 tests and the package build/TypeScript passed before main integration. Final release validation is recorded in Desktop context K.

Release review recovery: a determinate failed ordinary rebind save must not trap explicit organization return. That return discards the unsaved ordinary grant and selects again through `/return` with `confirmedOnly`; promoting an ordinary (possibly unknown-availability) grant would bypass the server policy. Uncertain publication remains blocked, and ordinary rebind cannot overwrite a pending explicit return. The regression first failed in three cases, then all 49 switch tests plus 15 personal fallback tests passed after the fix. Studio's same binding nonce remains session-scoped and valid when another issue is created; personal consent verification is stateless and can recheck the same proof during local commit.
